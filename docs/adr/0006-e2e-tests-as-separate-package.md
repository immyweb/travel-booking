# Playwright E2E tests live in their own package, not inside packages/web

E2E coverage of the booking journey (sign-in → search → listing detail → book → confirmation) lives in a new `packages/e2e` workspace, not colocated with `packages/web`'s own Vitest suite. Fixture setup needs to insert marker listings directly via drizzle and sign up throwaway users via Better Auth — the same DB/auth internals `packages/api`'s own integration tests reach into — and `packages/web` has no dependency on `@travel-booking/api` today (only on `@travel-booking/core`). Putting the E2E suite inside `packages/web` would introduce that dependency and make the frontend package reach into the backend's internals for test setup, inverting the existing layering. A separate package can depend on both `@travel-booking/api` and `@travel-booking/core` without either app package depending on the other.
