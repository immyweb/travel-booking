# Map tiles are fetched directly by the browser, not proxied through Express

The Search results map (MapLibre GL JS, OpenFreeMap tiles) loads vector tiles directly from the tile provider in the browser, rather than routing them through the Express API. This is the first case of the browser fetching anything from a third party without going through Express. [ADR-0002](0002-express-as-single-source-of-truth.md) mandates Express as the single source of truth so Next.js never reads data directly and future non-web consumers have one gateway — but that concern is about domain data (Listings, Bookings, Search results), not generic map imagery with no domain meaning. Map tiles carry no Listing/Booking data and aren't something a future mobile client would fetch through this API either way, so proxying them through Express would add a hop and a bandwidth cost for no gain in line with ADR-0002's own reasoning. ADR-0002's single-source-of-truth boundary therefore applies to domain data, not to third-party map tiles.
